# AGENTS.md

## Project
Multilingual Citizen Grievance Chatbot (Neural Storm 2026, HI-02).
Citizens file complaints in Gujarati, Hindi, Hinglish or English; the system
classifies the department, files a ticket, tracks status and escalates stale
tickets. Solo project, built with AI assistance.

## Stack
- Backend: Python 3.11, FastAPI, SQLModel, PostgreSQL, Alembic, APScheduler
- ML: PyTorch, Hugging Face Transformers (MuRIL), scikit-learn baseline
- Frontend: React, Vite, TypeScript, Tailwind, shadcn/ui, Recharts
- Tooling: ruff, mypy, pytest, pre-commit, Docker, GitHub Actions

## Architecture rules (never break these)
1. Layering: router -> service -> repository. Routers hold no business logic
   and no DB queries. Services never import FastAPI. Only repositories touch the DB.
2. The classifier is used only through the `Classifier` interface in `nlp/`.
3. All config comes from environment variables via pydantic-settings.
   No hardcoded secrets, URLs or magic numbers.
4. Every function has type hints. Every public function has a short docstring.
5. User-facing system messages come from the template files per language,
   never generated by an LLM.
6. No new dependency without a one-line entry in docs/DECISIONS.md.

## Quality gates (must pass before finishing any task)
- `make lint` (ruff + mypy) clean
- `make test` passes; new logic has tests
- No dead code, no commented-out code, no stray print statements (use logging)

## Documentation rule
After every meaningful change, update in the same task:
- docs/TASKS.md (status), CHANGELOG.md (what changed)
- docs/ARCHITECTURE.md if structure or data flow changed
- docs/DECISIONS.md if a technology or design choice was made
- README.md if setup or usage changed

## Workflow for every task
1. Read docs/TASKS.md and docs/ARCHITECTURE.md first.
2. State a short plan, then implement only what the task asks.
3. Run `make lint` and `make test`; fix failures until both pass.
4. Update docs (TASKS.md, CHANGELOG.md, and others per the documentation rule).
5. Commit directly to `main` with a Conventional Commit message, then stop.

## Git
- Work and commit only on `main`. Never create branches.
- One logical change per commit. Never bundle unrelated changes.
- Commit only when lint and tests pass. Never commit a broken build.
- Message format: `type(scope): short imperative summary`
  (feat, fix, docs, test, refactor, chore, ci).
- Stage files explicitly (`git add <paths>`), never `git add .` blindly.
  Check `git status` first: no .env, keys, datasets, model weights or caches.
- Never force-push, rewrite history, or amend pushed commits.
- Push to origin after each commit.

## Never
- Never invent metrics, results or screenshots.
- Never commit .env, keys, datasets or model weights.
- Never refactor unrelated code during a task.
- Never skip tests to make a task "pass".
